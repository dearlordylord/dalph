# MBT corpus inventory and replay provenance

The repository's MBT verifier selects the existing conformance drivers through
`pnpm test:mbt`. This slice inventories those selections and defines validation
before corpus consumption. It changes no Dalph runtime code, driver, assertion,
Vitest selection, or Quint model semantics. Ordinary and coverage tests still
exclude `packages/**/*.mbt.test.ts`.

Derived from issue #363. The checked-in
[manifest](../../scripts/mbt-corpus-manifest.json) is the single repository-owned
lane-to-corpus inventory. Refresh and check it with:

```bash
mise exec -- node scripts/mbt-corpus-contract.mjs --write
mise exec -- node scripts/mbt-corpus-contract.mjs --check
mise exec -- node --test scripts/mbt-corpus-contract.test.mjs
```

## Selected boundaries

The manifest contains all 15 currently selected files and 39 generation option
sites, including directed and mutant controls. Each `id` maps to exactly one
`corpus` path. Ordinals identify option sites in source order, not test counts.
Shared options used by a positive driver and a mutant driver map to the same
corpus; both replay consumers must remain. The `source` and `line` identify the
option site; `replayBoundaries[source]` records exact generator/replay call
expressions, including shared-options consumers, driver factories and state
checks. The manifest stores inline state-check expressions rather than renaming
or simplifying them. Full source digests also bind manual directed scenarios,
reverse checks, assertions after replay and production implementation imports.

Vitest first runs the `mbt` project with four workers, excluding accepted-result
integration. Its second project runs accepted-result integration alone with one
worker. Both resolve current workspace source, as checked by
[the source-resolution control](../../scripts/mbt-source-resolution.test.ts).
The workspace-source-resolution suite is selected but generates no corpus.

## Corpus and provenance contract

Manifest version 1 is a closed snapshot schema: `tools`, `budgets`, `selection`,
`modelClosures`, `replayBoundaries`, `lanes`, and `semanticInputs` must exactly
equal a freshly derived repository snapshot, including every nested key and
value. JSON object key order is immaterial; array order is semantic. Unknown,
missing, malformed or changed model/tool/options/seed fields fail validation.
Never refresh a manifest automatically in response to a replay failure.
`--write` is an explicit maintainer action, followed by review and controls.

A corpus file is a UTF-8 JSON array of complete ITF traces returned by the
pinned generator. Preserve ITF metadata, action names, nondeterministic picks and
all model states. A receipt has exactly these fields:

```json
{
  "version": 1,
  "lane": "result-recovery-direction/2",
  "provenanceSha256": "<SHA-256 of canonical validated manifest>",
  "corpusSha256": "<SHA-256 of exact corpus bytes>"
}
```

`corpusProvenanceDigest` recursively sorts object keys using the contract's
comparator and serializes compact JSON; arrays retain order. Receipts bind the
whole manifest, including options, seeds, model/import and replay source digests.
The corpus loader must read both files, derive the current expected manifest,
then call `validateCorpus(receipt, bytes, manifest, expectedManifest, laneId)`
before exposing any trace to a replay consumer. It rejects stale provenance even
when a stale receipt has been rehashed, corrupt bytes, unknown lanes, empty
traces, incorrect trace counts and excessive state/byte sizes. The pinned driver
and ITF decoder retain responsibility for trace action/state decoding.

Runtime replay must load a validated corpus and retain the same driver factory,
configuration, state check and post-replay assertions. It must never call
`quintRun` (which supplies live generation), `generateTraces`, the CLI, or a
fallback generator. A corpus-only `TraceGeneration` service may supply already
validated traces to `quintRunWithTraceGeneration`; its `generate` method must
fail on an option mismatch and have no live generation layer. This is the next
owner's wiring boundary. Existing MBTs still generate live traces in this slice;
no payload corpus or replay migration is claimed here.

The controls in [the contract tests](../../scripts/mbt-corpus-contract.test.mjs)
cover valid inventory/receipt acceptance; stale, missing and malformed model,
tool, options and seed refusal; deleted lanes; changed state checks; unknown
fields; corpus corruption; wrong lane; missing receipt; state-depth overflow;
and rehashed stale provenance. The validator has no generator import or fallback.

## Finite generation and replay budgets

The manifest sets a serial corpus-generation allowance of **30 minutes total**,
**10 minutes per option site**, **64 MiB per corpus**, and **256 MiB total**.
Replay has a separate **30-minute total**, **10-minute per-site** ceiling. These
are hard refusal limits for downstream generation/replay, not measured full-suite
performance promises. Existing Vitest test deadlines remain unchanged and may be
shorter; corpus wiring must preserve those deadlines. Run-mode corpus state
limits are exactly `nTraces * (maxSteps + 1)`; all selected run sites already
specify depth. Named-test corpora have a finite ceiling of **65,536 states per
trace**, without changing their Quint test body. Every site requires its existing
retained trace count; a partial file cannot count as a complete lane.

Generation owners must enforce decreasing total wall time, per-site process
custody and limits while writing, then validate before atomically publishing
complete bytes and receipts. Validation here enforces corpus byte/trace/state
bounds; it does not supervise downstream generation or infer generation time
from a receipt. Stop at the first incomplete/oversize/over-budget obligation,
retain its evidence and report the exact site before wiring. Do not shrink the
scenario set, depth or samples to fit. Eight legacy implicit-10,000-sample sites
are an explicit cost risk; their complete fit has not been established by this
bounded inventory. No expensive formal profiles were explored.

The planned-attempt suite additionally selects the existing reverse-observation
contract and direct Quint evaluator. Its frontier bounds remain 4,096 choices,
100,000 evaluations and 90 seconds per enumeration; its directed production
schedule has seed 158, and incomplete/cancelled/truncated collections must be
refused. The collection timeout negative control deliberately uses 25 ms.
These tests and the canonical-model guard-mutation control are not ITF generation
sites. Preserve them as executable controls alongside corpus replay; replacing
them with corpus membership would require a new accepted formal contract and is
blocked. Their model/helper source digests and `checkReverseTrace` consumers are
included in the manifest.
