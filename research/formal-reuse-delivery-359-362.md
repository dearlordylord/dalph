# Local formal reuse delivery evidence

A developer first verifies the integrated checkout, then runs the complete formal
profile or reuses its original stopped execution, and finally obtains that same
requirement during normal application handoff. This is the ordered #359 → #360 →
#361 → #362 feature, not four independent releases. This document retains chronological
intermediate checkpoints; the [final qualification report](formal-reuse-qualification-362.md)
records successful local acceptance at `49dc0dad7`. Earlier pending or failed
statements below describe their original checkpoint.

The accepted behavior remains in [#358's approved specification](https://github.com/dearlordylord/dalph/issues/358#issuecomment-5649238628)
and [#357's command/evidence contract](https://github.com/dearlordylord/dalph/issues/357#issuecomment-5649197858).
All four issues and their blocking relationships remain authoritative. These
changes concern repository verification commands, files and processes; they do
not change Dalph's tracker, executor, Git integration or workflow journal behavior.

## Scoped review closure

Standards/architecture review found no blocker in #360. The temporary
`validateOnly` API is explicitly assigned to #361's required final no-checker
caller; it must have that consumer before complete-feature closure. A possible
fixture/production toolchain type split was a judgment suggestion, not a
demonstrated violation: production obtains the shape only from its validating
resolver, and tests inject the controlled boundary deliberately.

Spec review found and closed three concrete gaps:

- A regular expression missed multiline/quoted Quint imports. The pinned lexer
  and file-source resolver now identify every import source, checked against
  the pinned parser grammar; corresponding controls
  pass.
- Apalache reads cwd/ancestor `.apalache.cfg` and actual JVM-home configuration.
  The resolver identifies JVM home, execution fixes it, and observation includes
  every implicit configuration's absence. Present unsupported configs fail;
  TLC uses the same identified Java/home. Focused controls pass.
- Synthetic record changes did not prove publication crashes. The real wrapper
  crash/reconciliation matrix above now proves the required before/during/after
  outcomes with real filesystem publication and process death.
